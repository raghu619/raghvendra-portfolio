The question

In an earlier project, StyleSense, I built a shopping assistant that filters products by budget, category and gender before it searches. It worked because the catalogue was synthetic and every product carried a clean category. Real catalogues don't.

So this project asks where category data comes from, and whether a model can fill it in: read a product's title and description, and pick its category from 141, such as Home & Garden > Decor.

How it's measured: every trained model is scored once on 2,497 products it never saw during training, by the share it puts in exactly the right category. For scale, a random guess gets 0.8% and always picking the most common category gets 2.0%. The LLM results so far come from a 100-product check, which carries about ±10 points of noise.

1

Clean the data

I started from Shopify's public product catalogue, 48,289 listings, and turned it into a dataset I could trust before training anything on it.

  • The answer was in the input. A field listing candidate categories contained the correct one for every product. Training on it would have measured lookup, not reading, so I removed it.
  • My first cleaning rule was wrong. A phone-number pattern matched 1,813 products, mostly clothing sizes and model years. Reading the matches led to a stricter rule that found the 74 real numbers.
  • Contact details in a public dataset. 283 listings had email addresses and 300 had URLs. All removed before publishing.
  • Very uneven categories. Some had 3 products, others thousands. I kept the 141 with at least 20 products and capped each at 500: 25,022 products, split 20,027 / 2,498 / 2,497 for training, validation and test.

A cleaning rule is a hypothesis until you read what it matched.

2

Rewrite every listing with an LLM

Listings ranged from a single word to pages of marketing copy, in English and six other languages. I had gpt-4.1-nano rewrite every product into the same four short lines in English (title, brand, description, details) through OpenAI's Batch API. The final run cost $0.77.

  • The first prompt invented facts. "12,5 cm" became "12 sheets". The second prompt fixed it, backed by a check in code that flags any number not in the original listing.
  • The third prompt looked better and wasn't. It fixed one problem but, across all 25,022 products, left more descriptions empty and invented more numbers. I kept the second.
  • Shorter and cleaner. The rewrites are 55% shorter than the originals.

A rule in a prompt is a request. A rule in code is a guarantee.

3

Set the bar with classic models

Before trying anything expensive, I measured what cheap classic models get from a 2,000-word bag of words. Logistic regression set the bar at 49.8%, in 5 seconds on a laptop. The rewrite from part 2 added 8.5 to 10.5 points to every model, and on listings in other languages it lifted accuracy from 15% to 48%.

The input mattered more than the algorithm: about 10 points from changing the text, at most 4 from changing the model.

4

Neural networks and LLMs with no training

I built a neural network in PyTorch, the 8-layer design from the course I'm following, and trained it one step at a time to see what training really does. It scored 25.5%, half of logistic regression. Removing all 7 hidden layers nearly doubled it.

The notebook measured three reasons:

  • The learning signal faded. By the first layer, the one that reads the words, it was 343 times weaker than at the last.
  • It memorised. 96% right on products it had seen, 25% on new ones.
  • It was confidently wrong. When it said it was 90% sure, it was right 38% of the time. Logistic regression, 88%.

One fix per problem. Skip connections and LayerNorm, the building blocks inside every transformer, brought 8 layers back to 49.9%. A single wide layer with dropout reached 53.5%, the first trained model to beat the bar.

The same network design does well in the course because it learns from 800,000 products to predict a single number, a price. Here it had 20,027 products and 141 categories. Neural networks need data.

Then I gave the task to LLMs with no training at all: the 141 category names, and a strict JSON schema that only accepts one of them. On a 100-product check, Gemini 2.5 Flash got 73% and GPT-5 mini 68%, ahead of everything I trained. gpt-4.1-nano got 38%.

Most of the big models' misses were in the right aisle, on the wrong shelf. That's this store's convention, not missing knowledge.

Small data favours simple models. With no data at all, big pretrained models win.

What went wrong, and what fixed it

The data contained the answerA candidate-categories field held the correct category for every product.
Removed it before training, so every score measures reading the listing, not looking up the answer.
A cleaning rule deleted real attributesA loose phone-number pattern matched clothing sizes and model years.
Printed every match before applying the rule, then wrote a stricter one: 74 real numbers instead of 1,813 matches.
The LLM rewrite invented numbers"12,5 cm" became "12 sheets".
A stricter prompt plus a number check in code. A third prompt that looked better was worse across all 25,022 products, so I rejected it.
Listings in seven languagesA bag-of-words model trained mostly on English can't read German or Japanese.
The rewrite translated everything into English: accuracy on non-English listings rose from 15% to 48%.
A deep network that couldn't learnThe learning signal was 343 times weaker at the first layer.
Skip connections and LayerNorm: from 25.5% to 49.9% with the same 8 layers.
Memorising, then confidently wrong96% right on seen products, 25% on new ones; right 38% of the time when 90% sure.
Dropout, keeping the best epoch on validation, and a calibration check for every model.
Paying for the same 141 names on every call2,048 of every prompt's 2,190 tokens were identical.
Put the fixed text first so OpenAI caches it: 69% cheaper per call, and cheaper than the Batch API for this job.
Notebooks hide stateRe-running one cell once broke a results table.
Every published notebook is re-run top to bottom, and LLM answers are saved, so a re-run never pays twice.

Tools

Python, pandas, scikit-learn, XGBoost and PyTorch for the models. The OpenAI API (Batch API, structured outputs, prompt caching) and OpenRouter for the LLMs. Hugging Face Datasets to publish the data, matplotlib for every chart, and Jupyter notebooks for each part.
