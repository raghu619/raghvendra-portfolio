Llama 3.2 in pictures

The whole idea

One picture first

The model has one job: read the text so far and guess the next token. Fine-tuning will teach it that after Category: the right next token is the product’s category.

1 · Chop

Cut the text into tokens

A model can’t read letters. A tokenizer cuts the text into pieces called tokens and swaps each one for its ID, a number from 0 to 128,255. A special start token always goes first.

Common words are one token. Rare words are cut into several pieces, which is why the model counts tokens, not words.

The examples are ready to go. Typing your own loads the real Llama 3 tokenizer, about 3 MB.

In the printout
  • Nothing yet. The tokenizer runs before the model, so the printout starts with what happens to these IDs.
2 · Look up

Give every token an arrow

The model keeps a table with one row for each of its 128,256 tokens. Each row is a list of 3,072 numbers. Think of that list as an arrow: each number says how far to go along one direction.

Training placed tokens with related meanings in similar directions. My StyleSense RAG project did the same with text-embedding-3-small, turning whole product descriptions into arrows. This table does it for single tokens, and a token’s row never changes with context.

We can only draw 2 of the 3,072 directions, so the map is a sketch. Positions are illustrative.

In the printout
  • (embed_tokens): Embedding(128256, 3072)The table: 128,256 rows of 3,072 numbers.
3 · Talk

Let the tokens talk

The problem: one arrow per token

␣case has one row, so it starts with the same arrow in phone case, pencil case and pillow case. One arrow can’t point at electronics, office supplies and bedding at once. The word before it knows which one you mean.

How a token asks

Attention lets each token pull in information from the tokens before it. Think of it as a small search that every token runs.

That’s attention: one question, a score for each earlier token, shares that add up to 100%, and a blend of messages added to the arrow.

Real attention also divides each score by √128 before softmax, which stops the shares from becoming all or nothing. The toy arrows here are short enough to skip that step.

It’s RAG inside the model

In StyleSense, a query embedding is compared with every product embedding and the best matches come back. Attention runs the same kind of search between tokens. The differences: every token gets a share instead of a top-k cut, and the question, label and message are all learned in training.

In the printout
  • (self_attn): LlamaAttention(Talk.
  • (q_proj): Linear(in_features=3072, out_features=3072, bias=False)Makes each token’s question.
  • (k_proj): Linear(in_features=3072, out_features=1024, bias=False)Makes each token’s label.
  • (v_proj): Linear(in_features=3072, out_features=1024, bias=False)Makes each token’s message.
  • (o_proj): Linear(in_features=3072, out_features=3072, bias=False)Turns the blended messages into one edit.

24 questions at once

One search can look for one kind of thing, so each layer runs 24 searches side by side, called heads. One head might look for the item type, another for colours, another for the word just before.

That’s where the 1,024 in the printout comes from: 8 shared sets × 128 numbers. The questions still need 24 × 128 = 3,072. The saving matters while the model writes, because it keeps every earlier token’s labels and messages in memory. At 8,192 tokens of text that’s 0.94 GB instead of 2.82 GB.

In the printout
  • (q_proj): … out_features=307224 heads × 128 numbers.
  • (k_proj): … out_features=10248 shared sets × 128.
  • (v_proj): … out_features=10248 shared sets × 128.

Keeping track of word order

A search by similarity can’t tell phone case from case phone: same tokens, same scores. So before matching, every question and label is turned like a clock hand, one notch further for each position in the text.

Turning both hands by the same amount leaves the angle between them alone, so the match depends on how far apart two tokens are, not on where they sit. Llama turns 64 hands per head, some fast and some very slow, so it can tell neighbours apart and also measure long distances.

In the printout
  • (rotary_emb): LlamaRotaryEmbedding()The clock. The brackets are empty because it follows a fixed rule, with nothing to learn.
4 · Think

Let each token think

After talking, each token thinks on its own. The MLP is a bank of 8,192 detectors. Each detector checks the arrow against its own direction, as if asking “is this a phone accessory?”. Detectors that fire add their own arrow back.

This is where knowledge from training gets written into a token, like “phone cases are electronics accessories”. Real detectors rarely mean one tidy thing, so treat the labels as a cartoon of the idea.

5 · Repeat

Keep steady, add, repeat 28 times

Keep the arrows a steady size

Every step adds to the arrows, so some could grow huge and drown out the rest. Before each talk and each think, the model rescales every arrow to the same size and keeps its direction. OpenAI’s embeddings come with length 1 for a similar reason: comparing two of them then compares only direction.

After rescaling, each of the 3,072 numbers gets its own learned volume knob, so directions can shift a little.

Add, don’t replace

Talk and think never overwrite a token’s arrow. They add an edit to it, so nothing learned earlier is lost. One layer is these six moves:

  1. rescaleinput_layernorm
  2. talkself_attn
  3. + addthe edit
  4. rescalepost_attention_layernorm
  5. thinkmlp
  6. + addthe edit

The printout lists the two rescale lines last, but they run first. A printout shows the parts, not the order they run in, the way Android Studio’s Layout Inspector shows a view tree.

28 layers

Llama stacks 28 of these layers. They share one design, and each has its own weights, like 28 objects of one class with different field values. Drag the slider to watch the arrow for the last token, :, collect its edits. This is the token that will make the guess.

The path is illustrative. Real layers move the arrow in all 3,072 directions at once.

I hit this wall in my catalogue project. An 8-layer network barely learned: the training signal reaching its first layer was 343 times weaker than at its last. Adding these same two ideas, the add and the rescale, took it from 25% to 50% accuracy.

In the printout

  • (input_layernorm): LlamaRMSNorm((3072,), eps=1e-05)Rescale before talking.
  • (post_attention_layernorm): LlamaRMSNorm((3072,), eps=1e-05)Rescale before thinking.
6 · Score

Score every token, pick the best

After layer 28 and one last rescale, the arrow for : is compared with the arrow of every token in the vocabulary, all 128,256 of them. It’s the dot product again: a token whose arrow points the same way scores high.

It’s one more vector search, with the whole vocabulary as the collection. Llama 3.2 reuses the lookup table from chapter 2 for it, so lm_head adds no new numbers.

The answer comes out one token at a time. ␣Electronics picks the aisle. Then the whole machine runs again, with that token added to the text, to pick the shelf.

In the printout
  • (norm): LlamaRMSNorm((3072,), eps=1e-05)The last rescale.
  • (lm_head): Linear(in_features=3072, out_features=128256, bias=False)A score for every token, using the lookup table’s rows.

8 · Next

Where fine-tuning plugs in

Training all 3.2 billion numbers needs far more memory than a free Colab GPU has. LoRA freezes every number in the printout and clips two thin strips onto some of the Linear layers. Only the strips learn.

Strips can go on the seven Linear lines: q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj and down_proj. Rescales, the dimmer and the clock have nothing a strip can attach to. In QLoRA, the frozen square is also stored in 4 bits to save memory, while the strips train at higher precision.

Check yourself

Can you explain it back?

Say each answer out loud before you open it.

Why can’t the lookup table alone tell a phone case from a pencil case?

Each token has one fixed row, so ␣case starts with the same arrow every time. Only attention to ␣phone or ␣pencil can move it.

In attention, what do the gold, blue and green arrows stand for?

Gold is the question a token asks (q_proj). Blue is the label every token shows (k_proj). Green is the message that gets added (v_proj, then o_proj).

Why are k_proj and v_proj 1,024 wide when q_proj is 3,072?

The 24 question heads share 8 sets of labels and messages: 8 × 128 = 1,024. It saves memory while the model writes.

Where do most of the 3.2 billion numbers live?

In the MLPs, the thinking step: about two thirds of the model.

When you fine-tune with LoRA, what learns and what stays frozen?

Only the thin strips learn. Every number in the printout stays frozen.
